## 3. Électronique — Détecteur de luminosité

### Ce que j’ai réalisé

- Réaliser un **détecteur de luminosité**.
- Utiliser un capteur permettant de mesurer la luminosité ambiante.
- Programmer le système pour allumer automatiquement une lampe lorsqu’il fait sombre.
- Comprendre le principe d’un système d’éclairage automatique.

### Comment ça se fait

1. Utiliser un **capteur de luminosité** pour mesurer la lumière ambiante.
2. Le capteur fournit une valeur correspondant au niveau de luminosité.
3. Le programme lit cette valeur.
4. Définir un **seuil de luminosité**. on a pris l'exemple de 30secondes.
5. Comparer la valeur mesurée avec le seuil.
6. Si la luminosité est faible, le système commande l’allumage de la lampe.
7. Si la luminosité est suffisante, la lampe reste éteinte.

### Principe

**Capteur de luminosité → Mesure → Comparaison avec un seuil → Commande → Lampe**

### Exemple de fonctionnement

**Il fait jour → luminosité élevée → lampe éteinte**

**Il fait sombre → luminosité faible → lampe allumée**

## 5. Discussion sur les projets FabLab

## 5. Design Thinking et conception des projets FabLab

### Ce que j’ai appris

- Découvrir la méthode du **Design Thinking** pour concevoir un projet.
- Comprendre qu’il faut partir du **problème ou du besoin** avant de chercher une solution.
- Comprendre l’importance de l’**empathie** pour bien identifier les besoins de l’utilisateur.
- Apprendre à transformer une idée en **croquis**, puis en plan ou prototype.
- Découvrir l’importance de l’**idéation** pour proposer plusieurs solutions avant de choisir la meilleure.
- Comprendre l’importance du **prototypage** et des tests pour améliorer progressivement une solution.

### Les étapes du Design Thinking

**Empathie → Définition du problème → Idéation → Prototype → Test → Amélioration**

#### 1. Empathie

L’objectif est de comprendre l’utilisateur, ses besoins, ses difficultés et son environnement.

**Comment ça se fait :**
- Observer les utilisateurs.
- Écouter leurs besoins.
- Poser des questions.
- Identifier leurs difficultés.
- Éviter de supposer directement la solution.

#### 2. Définition du problème

Après avoir observé et compris les besoins, il faut formuler clairement le **problème à résoudre**.

**Principe :**

**Problème → Besoin → Objectif**

Il faut éviter de commencer directement par une solution.

#### 3. Idéation

L’idéation consiste à rechercher plusieurs solutions possibles au problème identifié.

**Comment ça se fait :**
- Faire un brainstorming.
- Proposer plusieurs idées.
- Comparer les différentes possibilités.
- Sélectionner les idées les plus pertinentes.

### ⚠️ Pièges observés pendant la formation

#### La solution avant le problème

Une erreur consiste à avoir déjà une solution en tête avant d’avoir identifié le problème.

**Mauvaise démarche :**

**Solution → Recherche d’un problème**

**Bonne démarche :**

**Problème → Besoin → Recherche de solutions**

#### L’idéation « polie »

Il faut éviter de rejeter ou de juger trop rapidement les idées proposées pendant la phase d’idéation.

L’objectif est d’abord de **générer plusieurs idées**, puis de les analyser et de sélectionner les meilleures.

**Idéation → Plusieurs idées → Analyse → Sélection**

#### 4. Croquis devenu plan

Une idée peut commencer sous la forme d’un simple **croquis**.

Elle est ensuite progressivement précisée pour devenir un **plan** permettant de réaliser le prototype.

**Idée → Croquis → Plan → Prototype**

Le croquis permet de visualiser rapidement l’idée avant de passer à une conception plus précise.

#### 5. Prototype

Le prototype est une première version concrète de la solution.

Il permet de vérifier :
- la forme ;
- les dimensions ;
- le fonctionnement ;
- l’utilisation ;
- les éventuels problèmes.

Le prototype n’a pas besoin d’être parfait. Il sert surtout à **apprendre et améliorer la solution**.

#### 6. Tester

Après la réalisation du prototype, il faut le tester dans les conditions prévues.

**Comment ça se fait :**
1. Utiliser le prototype.
2. Observer son fonctionnement.
3. Identifier les problèmes.
4. Recueillir les retours des utilisateurs.
5. Modifier la conception.
6. Réaliser un nouveau prototype si nécessaire.
7. Recommencer les tests.

### Méthodes de réalisation d’un projet

#### Méthode en cascade

La méthode en cascade consiste à avancer étape par étape, dans un ordre défini.

**Besoin → Conception → Fabrication → Test → Produit final**

Chaque étape est réalisée avant de passer à la suivante.

### Méthode en spirale

La **méthode en spirale** consiste à développer un projet progressivement, en réalisant plusieurs cycles de conception, de prototypage, de test et d’amélioration.

**Idée → Conception → Prototype → Test → Retour → Amélioration → Nouveau prototype → Test → ...**

À chaque cycle, on analyse les résultats obtenus afin d’améliorer la solution.

**Principe :**

**Concevoir → Réaliser → Tester → Observer → Améliorer → Recommencer**
